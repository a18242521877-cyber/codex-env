# 推广台

拼多多店铺的本机推广监控。扫码登录后查看推广计划、测图、测款，并生成**每日总结**和**调整方案**。

新安装默认是**真实店铺**：在本机弹出浏览器，打开 [拼多多商家后台](https://mms.pinduoduo.com/login/)，用「拼多多商家版」扫码。登录后的 Cookie 只留在这台电脑上。没有账号时，登录页可以改成**模拟店铺**，用虚构的「云岭家居旗舰店」把流程走完。

## 技术选型

- **Python 3.11+** 和标准库里的 HTTP 服务、SQLite。Windows 上装好 Python 就能跑，不需要 Node.js。
- **界面是本机网页**，由 Python 只在 `127.0.0.1` 上提供。中文、离线，不从 CDN 拉字体或脚本。
- **Windows 桌面窗口用 pywebview**，底层是系统自带的 Edge WebView2。没有装这个库时，自动改用系统浏览器打开同一地址。这扇窗口只是推广台自己的界面。
- **真实店铺登录用 Playwright**。优先启动本机 Microsoft Edge；没有 Edge 时用 Playwright 下载的 Chromium。浏览器里打开的是商家后台官方页面，由店主自己扫码。验证码、短信也在这个窗口里完成。
- **规则在本地计算**。每日总结和调整方案读的是已经写入 SQLite 的数字，不调用外部大模型，经营数据不出这台电脑。

没有选用 Electron：体积大，而且这台工具的工作主要是本地数据和规则，不需要一套 Node 构建。

## 功能

登录后可以看：

- 总览：花费、成交额、ROI、订单、点击率、转化率，以及近 14 日花费
- 推广计划：搜索推广、场景推广、全站推广，含日预算和出价
- 测图：同一商品多张主图的点击率、转化率
- 测款：商品阶段、花费、ROI、预算使用率、加购
- 每日总结：中文复盘、亮点、风险、环比
- 调整方案：放量、小幅加预算、暂停、先改详情、换主图、停测图、继续观察

另外做了这些：

1. 真实店铺扫码登录，或模拟店铺无账号体验
2. 可解释的本地规则，阈值能改
3. 今天的预算节奏（消耗偏快 / 偏慢）
4. 建议可标记已执行或已忽略，重新计算不会丢掉状态
5. 预警列表
6. 导出 UTF-8 BOM 的 CSV（Excel 可直接打开中文）和 Markdown 日报
7. 复制调整方案、打印日报
8. 登录后按间隔自动同步（默认 30 分钟，可关）。真实店铺自动同步会再弹出浏览器
9. 操作日志
10. 清空本地数据（设置保留）
11. 页面里的口径说明
12. `python run.py --self-test` 自检

## 在 Windows 上运行

1. 安装 [Python 3.11 或更高版本](https://www.python.org/downloads/windows/)。安装时勾选 **Add python.exe to PATH**。
   如果输入 `py -3` 打开了微软商店，到「应用执行别名」里关掉 `python.exe` / `python3.exe` 的商店跳转。
2. 打开命令提示符，进入本仓库目录：

```bat
py -3 -m venv .venv
.venv\Scripts\activate
pip install -r requirements-windows.txt
python -m playwright install chromium
python run.py
```

`python -m playwright install chromium` 会下载一套 Chromium。电脑上已经有 Edge 时，登录窗口会优先用 Edge，但这条安装命令仍然建议执行，避免 Edge 启动失败时没有退路。

WebView2 一般随 Windows 11 和较新的 Windows 10 提供。若推广台自己的窗口提示缺少运行库，安装微软的 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)，或先用 `--browser`。商家登录用的是 Edge / Chromium，不是这扇 WebView2 窗口。

也可以在装好依赖后双击仓库根目录的 `启动推广台.bat`。脚本会优先使用 `.venv`。

窗口打不开时：

```bat
python run.py --browser
```

只启动服务、自己打开地址：

```bat
python run.py --serve
```

默认地址是 `http://127.0.0.1:8765/`。端口被占用时：

```bat
python run.py --port 8766
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m playwright install chromium
python run.py --browser
```

`requirements.txt` 含二维码、Playwright 和读取 xlsx 的 openpyxl。桌面窗口的 `pywebview` 写在 `requirements-windows.txt`，避免在没有 GTK/Qt 的环境里安装失败。

## 登录

### 真实店铺

1. 打开推广台。新安装的数据模式是「真实店铺」。已经用过的库会保留你上次保存的选择，在登录页点「真实店铺」即可。
2. 程序弹出 Edge（或 Chromium），打开 `https://mms.pinduoduo.com/login/`。请用**拼多多商家版** App 扫这个窗口里的二维码。个人版拼多多扫不了商家后台。
3. 推广台页面上会尽量截一张同样的二维码。**请扫弹出的浏览器窗口**，不要对着截图再拍一张。短信或验证码在那个窗口里自己完成，程序不会代点、也不会绕过。
4. 扫码成功后页面会显示「正在读取推广报表」。这时**不要点「重新打开登录」**。程序已经把登录记下并进入店铺，再从商家后台跳进推广中心（先打开 `mms.pinduoduo.com`，再用后台自己的登录跳转进入 `yingxiao.pinduoduo.com`）。直接打开营销域名常常停在首页，只能收到店铺资料，没有花费。若弹出的窗口停在首页，请点一次「推广中心」或「商品推广」，停留在能看到花费的页面。程序会点这些入口和「近7天」这类日期，并点已经生成好的「下载 / 导出」；**不会**点「生成报表」。报表没识别到商品也会保持已登录。页面若一直停在登录、但本机已经有扫码文件，点「用已保存登录进入」。
5. 这次收下的接口地址写在 `pdd-session/last_capture.json` 开头的 `debug.urls` 里（只有路径，不含查询参数，避免把临时令牌写进文件）。如果里面全是商家首页、没有 `report` / `promotion` / `goods`，说明还没进到推广报表。
6. 会话写在数据库旁边的 `pdd-session/storage_state.json`，权限尽量收成只有当前用户能读。数据库里的会话标记只是 `storage` 这几个字，不保存 Cookie 原文。Cookie 一落盘就会进入店铺，哪怕报表还没识别完。
7. 停在登录页、但电脑上已经有扫码文件时，点「用已保存登录进入」。下次打开也会直接用这份登录，不必再扫一次。
8. **退出**会关掉这次登录，并删除 `pdd-session` 里的文件。已经同步进 SQLite 的报表还在。换店也要先退出，再扫新的码。

真实店铺没有登录文件时，点「同步」会提示先扫码，不会编造数字。

### 模拟店铺

1. 登录页改成「模拟店铺」。二维码内容是本机票据 `pddmon://mock-confirm?...`，手机去扫**不会**登录拼多多。
2. 点「模拟已在手机确认」进入云岭家居旗舰店，并写入近 15 天演示数据。
3. 退出只删除本机登录会话，历史报表还在。

## 数据放在哪

| 系统 | 默认路径 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\pdd-promo-monitor\monitor.sqlite` |
| macOS / Linux | `~/.local/share/pdd-promo-monitor/monitor.sqlite` |

可用环境变量换位置，程序里没有密钥：

- `PDD_MONITOR_DB`：SQLite 文件路径
- `PDD_MONITOR_PORT`：端口

复制这个 sqlite 文件就是备份。真实店铺的浏览器会话在它旁边：

```text
pdd-session/storage_state.json   登录态。退出登录或清空数据时删除
pdd-session/last_capture.json    最近一次收下的报表正文摘要，不含 Cookie 请求头
```

退出登录不会删 sqlite 里的报表。设置页「清空本地数据」会删店铺、报表和上面的会话文件，阈值保留。这两个文件不要打包发走，也不要提交到仓库。

服务只监听 `127.0.0.1`。会改数据的请求还要带本机页面才会加的请求头，避免别的网页顺手调用。

## 口径

- **店铺合计、每日总结**用测款（商品）日报，避免和计划重复相加。
- **推广计划**单独展示。模拟数据里，计划数字等于名下商品之和。
- **测图**是创意层，不计入店铺花费。
- ROI = 成交额 / 花费。点击率 = 点击 / 曝光。转化率 = 订单 / 点击。
- 模拟成交额 = 订单 × 标价。真实店铺用报表里的交易额，不再用标价去乘。
- 金额在库里用「分」，页面上用「元」。
- 真实报表的金额没有统一单位。CSV / xlsx 按「元」；JSON 里的整数按「分」，小数按「元」。后台若改口径，花费可能差 100 倍，请对照商家后台核对，不要只信这里的换算。
- 测图只有报表里出现创意或主图维度才有。很多店铺只有商品报表，测图页会是空的，这不是同步失败。

## 调整规则

测款和测图看**最近 7 个完整日**。如果你选的是今天，这两类规则截止到昨天，避免上午量少被当成下滑。预算节奏只在查看今天时出现。

默认阈值（设置里可改）：

| 情况 | 建议 |
| --- | --- |
| 7 日 ROI ≥ 3，订单 ≥ 30，预算使用率 ≥ 75% | 日预算 +30% |
| 7 日 ROI ≥ 目标 2，订单在涨，使用率 ≥ 60% | 日预算 +10% |
| 点击率 ≥ 3% 且转化率 < 2% | 先改详情、价格或评价，不加预算 |
| 7 日 ROI < 1 且花费 ≥ 200 元 | 暂停 |
| 曝光或订单不够，花费也不高 | 继续观察 |
| 两张图曝光都 ≥ 3000，胜出图点击率 ≥ 次优的 1.25 倍，转化率不明显更差 | 把胜出图设为主图；点击率不到胜出图 60% 的图停止测试 |
| 样本够了但最好的图点击率仍 < 1.5% | 重做创意 |
| 计划 ROI 低于目标 | 搜索/场景降出价约 10%；全站收预算 20%。若名下商品已经建议暂停或改详情，计划级不再重复收 |
| 计划 ROI 达到放量线且使用率 ≥ 90% | 上调计划日预算 |
| 今天 10 点到 20 点，按当前速度外推会明显超预算 | 消耗偏快，临时降价或收限额 |
| 今天 14 点之后，ROI 仍达标但预算花不完 | 消耗偏慢，出价上调 5%～10% |

商品级建议优先于计划级。这些是本机提醒，不会自动改拼多多后台。


## 已知限制

- 拼多多没有稳定的公开推广 API。本工具不猜测签名，也不绕过风控。能拿到的数据，只是登录后官方页面自己加载或允许下载的那一部分。营销域名需要从商家后台跳进去；只停在首页时，捕获里会是店铺资料而没有花费。页面改版后，二维码可能截不到、字段可能对不上。对不上时会提示没识别到，并保留登录，方便你打开报表后再同步。
- 自动同步在真实店铺下会弹出浏览器。不想被打断，把间隔设为 0，需要时再点「同步」。
- 演示店铺的数字是按规则编的，不是某家店的真实成绩。
- 调整方案是规则，不是自动改价、改预算。
- 单用户、单机。没有账号体系和云同步。
- 不提供单文件安装包。Windows 上以 Python 源码运行。
